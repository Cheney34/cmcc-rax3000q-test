# 刷机教程（RAX3000Q / RAX3000QY）

> 前提：你的机器**已经刷好了 NWrt / 第三方 U-Boot**，能用 `192.168.1.1` 的 U-Boot 网页刷镜像。
> 已经刷过一次就意味着**引导层不用再动**，本仓库的产物都是「应用层镜像」，刷坏了随时重进 U-Boot 网页再刷。

---

## 0. 先看清楚你手上是哪种机器

| 机型 | 说明 |
|---|---|
| **RAX3000Q**（=`cmcc,rax3000q`）| 中国移动定制版，官方 OpenWrt 里的设备名 |
| **RAX3000QY** | 同硬件的移动版本，U-Boot 与分区一致，两者固件通用 |

硬件：ipq5018（ipq50xx）+ 5G（QCN61xx，DTS 里的 `&wifi1`）+ SoC 内置 2.4G，128 MB NAND（GigaDevice GD5F1GQ5REYIG）/ 256 MB RAM，QCA8337 交换机（1 WAN + 3 LAN）。
本仓库两条轨道的产物**都是给这个硬件**的，可以直接互刷。

> ⚠️ 256 MB RAM 是这台机器的硬约束：上游 OpenWrt 甚至在 DTS 里**默认把 Wi-Fi 关掉**来避免 OOM
> （原话：`Due to the limited 256 MiB RAM, ath11k is disabled in the DTS to avoid OOM issues on this device.`）。
> 本仓库的轨道 A 会在构建时自动打补丁把 Wi-Fi 重新打开（`enable_wifi` 默认为 `true`），见 §3。

---

## 1. 进入 U-Boot 网页（刷机入口）

1. 用网线把电脑接到路由器的 **LAN1** 口。
2. 电脑网卡改成**静态 IP**：
   - IP：`192.168.1.2`（若进不去，改试 `192.168.1.8`）
   - 掩码：`255.255.255.0`
   - 网关：`192.168.1.1`（可以不填）
3. 路由器**断电** → 按住 **Reset** 键不放 → 插电 → **保持约 10 秒**后松开。
4. 浏览器打开 **http://192.168.1.1**，会出现 U-Boot 的刷机页面。
   - 若打不开：换 LAN2/LAN3 试；确认电脑没用代理；换浏览器（有些页面只吃 HTTP 不吃 HTTPS）。

> 这一步没有任何「刷」的动作，随时可以断电重来，不会变砖。

---

## 2. 刷哪个文件

下载 Actions 的 artifact（或 Release）后，里面的镜像按下面选：

### 轨道 A（官方 mainline，**默认只刷这个**）
| 文件 | 用途 |
|---|---|
| `openwrt-qualcommax-ipq50xx-cmcc_rax3000q-squashfs-factory.ubi` | **U-Boot 网页刷这个**（约 11.5 MB）|
| `openwrt-qualcommax-ipq50xx-cmcc_rax3000q-squashfs-sysupgrade.bin` | 已经跑 OpenWrt 时在 LuCI 里「系统 → 备份/刷写固件」升级用 |
| `openwrt-qualcommax-ipq50xx-cmcc_rax3000q-initramfs-uImage.itb` | 救砖/临时启动（内存运行，不写 flash）|

### 轨道 B（ImmortalWrt QSDK 完整 NSS，可选实验）
| 文件 | 用途 |
|---|---|
| `*-cmcc_rax3000qy-squashfs-nand-factory.bin`（名字里带 nand / factory）| **U-Boot 网页刷这个** |
| `*-squashfs-sysupgrade.bin` | 已跑 OpenWrt 时升级用 |

### 如果 U-Boot 网页拒收 `.ubi`
说明你的 U-Boot 只认「整盘镜像」或只认 `.bin`。按顺序试：
1. 改传 `-squashfs-sysupgrade.bin`（部分 U-Boot 会按 raw 写入 flash）。
2. 还是不行 → 直接用**轨道 B** 的产物（NWrt 系镜像天生是整盘格式，与你的 U-Boot 同源）。
3. 或走 §5 的 TTL 控制台路径：官方上游给出的刷写流程就是串口 + TFTP，
   `tftpboot 192.168.10.19:<你的固件>.ubi` → `flash rootfs` → `reset`
   （`192.168.10.19` 是你 PC 上 TFTP 服务的地址；这条路径**不写 `0:art` 分区**，所以 MAC/射频校准安全）。

> 这一步是本教程里**唯一有不确定性**的地方：官方 `.ubi` 是标准 UBI 卷镜像，能不能被第三方 U-Boot 网页直接接受取决于你 U-Boot 的版本。
> 判断方法：先在 U-Boot 页面里看它接受的文件类型说明，或看它的「固件格式」提示。
> **刷写本身不会损坏 U-Boot**，最坏结果只是系统区被写坏、需要重进 U-Boot 再刷一次。

## 3. 刷完第一次开机

1. 电脑网卡改回 **自动获取 IP（DHCP）**，网线接 LAN 口。
2. 浏览器打开 **http://192.168.1.1**（若轨道 B 的默认网段不同，看路由器贴纸或试 `192.168.10.1`）。
3. 登录：用户 `root`，密码**空**。
4. **立刻设密码**：「系统 → 管理权 → 修改密码」。
5. 检查四件事：
   - **Wi-Fi**：正常应出现 **2.4G 与 5G 两个 SSID**（首次开机开无线电会慢 30~60 秒；256 MB 机器请耐心等）。
     没有 Wi-Fi 的话按 §3.1 排查。
   - **IPv6**：把 WAN 接上上级，看「状态 → 概览」是否拿到 IPv6 地址与 PD 前缀；下游设备应该也能拿到公网 v6。
   - **Portal 认证**：见 §4（**它没有 LuCI 菜单**，这点和你想的不一样，别以为没装上）。
   - **接口 MAC**：SSH 里执行 `rax-mac show`，四个口的 MAC 应该是连号派生而不是重复。

### 3.1 如果开机没有 Wi-Fi

上游默认关 Wi-Fi，本仓库靠**构建时打补丁**（`official/scripts/enable-wifi.py`）重新打开，取决于两个条件：

1. **补丁是否生效**：看 Actions 产物里的 `wifi-patch.txt`，应该有 `enable wifi: ...` 之类输出；
   如果显示「未找到 DTS」，说明上游把文件挪了，需要手改脚本或手动给 DTS 加 `status = "okay"`。
2. **板级 BDF / 固件是否齐**：官方 `cmcc_rax3000q` 这个 profile 的 `device_packages` 是**空的**，
   意思是官方**默认不给它装 ath11k 固件和板级 BDF**。工作流会自动探测并补上
   （优先 `ipq-wifi-cmcc_rax3000q`，没有就退用同平台的 `ipq-wifi-cmcc_mr3000d-ci`，日志里会 `::warning::` 提示）。
   对应的包名会写进产物里的 `missing-packages.txt` / 构建日志，可据此在 SSH 里 `apk add` 或下次构建时改 `official/config.seed`。

SSH 排查命令：

```sh
dmesg | grep -i -E 'ath11k|q6|firmware|bdf'   # 看固件加载与 BDF 报错
iwinfo                                         # 有没有 wlan0/wlan1
ls /lib/firmware/ath11k/                       # 固件在不在
apk list --installed | grep -i -E 'ath11k|ipq-wifi'
# 手动补（示例）
apk update && apk add ath11k-firmware-ipq5018-qcn6122 ipq-wifi-cmcc_mr3000d-ci
wifi reload
```

> 注意：如果 5G 起不来，多半是 **BDF 不匹配**（板级校准数据是每台机器/每个 FEM 组合专用的），
> 这不是「编译错」，而是官方设备支持本身还在完善。可以先用 2.4G，或去上游 issue 反馈。

## 4. Portal（网页认证）默认行为

固件预置的 portal 是 **OpenNDS**（`opennds` 包，25.12/snapshot 里它在 routing feed）。

> **重要：OpenNDS 没有官方 LuCI 应用**（官方 luci feed 里没有 `luci-app-opennds`）。
> 配置入口是 UCI 配置文件 `/etc/config/opennds`，实时状态用命令 `ndsctl status`。
> 首次启动时 `95-portal` 已经帮你配好了，日常不用动。

首次启动的默认策略（写入 `/etc/config/opennds`）：

- 模式：**网关模式（gateway）**，接口 = `br-lan`；未认证客户端的上网请求被劫持到门户页。
- 认证方式：`login_option_enabled='1'` → **「Dynamic Click to Continue」一键上网**（点一下即放行，接受条款）。
- `gatewayfqdn='disable'`：**故意关掉**，否则 openNDS 会霸占网关 80 端口，LuCI 都打不开。
- 会话时长 12 小时（`sessiontimeout=720` 分钟），空闲 30 分钟 / 认证后空闲 120 分钟踢下线。
- 放行：DNS(53/TCP+UDP) 与 DHCP(67/UDP) 永远放行（这是 openNDS 的硬要求，去掉会把自己锁死）；
  另外放行 SSH(22)、HTTP(80)、HTTPS(443) 以方便你自己管理。
- 内存：`max_page_size=4096`（默认 10240），为 256 MB RAM 省内存。

常用操作：

```sh
ndsctl status                 # 在线客户端、已认证客户端
ndsctl clients                # 列表
ndsctl stop / ndsctl start    # 临时启停（不改开机自启）
/etc/init.d/opennds stop && /etc/init.d/opennds disable    # 彻底不用 portal
/etc/init.d/opennds enable && /etc/init.d/opennds start    # 再打开
```

**想要「用户名 / 密码」登录**（而不是一键上网）：SSH 里执行

```sh
uci set opennds.@opennds[0].login_option_enabled='2'   # 2 = Username/Email Login
uci commit opennds && /etc/init.d/opennds restart
```

> 自主模式（openNDS 自己出页面）时，登录页由本机的 theme 脚本生成，见 `/usr/lib/opennds/`。
> 要让认证页面走你自己的外部服务器（FAS），才需要配 `fasport`/`fasremoteip`/`faspath`/`faskey` —— 本仓库默认不用外部服务器。
> 另外：一旦你加过任何自定义 `users_to_router` 条目，**必须显式保留 DNS(53) 与 DHCP(67)**，
> 官方文档原话是去掉它们会「soft brick your router」。

## 5. 备份 / 救砖 / 回退

### 5.1 第一次刷之前（如果还能进原厂系统）
```sh
# 在原厂系统里导出关键分区（有 SSH 时）
cat /proc/mtd
dd if=/dev/mtd1 of=/tmp/mibib.bin     # 分区表
dd if=/dev/mtd2 of=/tmp/art.bin       # 射频校准 + MAC（最重要，丢了 Wi-Fi 就废）
# 再用 scp / tftp 弄到电脑上存好
```
**`art` 分区是唯一「丢了就找不回来」的东西**，务必先备份。官方分区布局里它挂在 UBI 卷 `0:art`（原厂系统里是 mtd13）。

### 5.2 刷坏了怎么办
因为 U-Boot 还在，恢复很轻松：
1. 重新按 §1 进入 U-Boot 网页。
2. 刷回任一可用镜像（轨道 A 或轨道 B 的产物都行）。
3. 实在进不去 U-Boot 网页 → 走 **TTL 串口**（115200 8N1，接主板 TX/RX/GND，3 针）：
   - 进 U-Boot 命令行后用 `tftpboot` 从电脑传镜像，再用 `nand erase` / `nand write` 或 `ubiformat` 写入。
   - 具体命令随 U-Boot 版本不同，见你刷 U-Boot 时用的那份教程（NWrt 的 TTL 教程文档）。

### 5.3 从轨道 A 换到轨道 B（或反过来）
直接重复 §1 + §2，用对方的镜像刷一次即可。**不需要**重刷 U-Boot、不需要改分区表。

### 5.4 回到原厂固件
只有在你备份过原厂分区/整盘镜像的前提下才能回。所以 §5.1 很重要。

## 6. 装软件包

### 轨道 A（官方 apk）
```sh
# 注意：OpenWrt 25.12/snapshot 用 apk，不是 opkg
apk update
apk add luci-app-ttyd              # 用户态包：永远能装
apk add kmod-usb-storage-uas       # 内核模块：只有当这次构建的 ref 与官方快照同源时才能装
                                   # （默认跟 main HEAD 走，内核更新 → vermagic 不同 → 官方 kmod 装不上，属预期）
```

### 轨道 B（ImmortalWrt 21.02 opkg）
```sh
opkg update
opkg install luci-app-ttyd
# 只能装 openwrt-21.02 时代的包，装不了官方 OpenWrt 的包
```

两者都可以在 LuCI → 系统 → 软件包 里图形化安装。
